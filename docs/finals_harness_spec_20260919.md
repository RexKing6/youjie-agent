# 有界 Agent Harness 主演示

## 范围
一条订单X主线：意图 → 动态选择调查工具 → Wiki出处与范围核验 → 必要的人类补证循环 → 缺口与供货调查 → 三案决策 → 人工批准 → ERPNext/OpenMES真实测试实例草稿和回读 → 变化使旧审批失效。
不修改PPT、不公开部署、不发送真实供应商邮件、不作设备控制或库存过账。业务条件为模拟，软件实例真实。固定工作流也能循环，本对照只证明当前固定清单与动态选择在相同资源和安全门槛下的差异。

## 运行结构
一个LangGraph编排Agent。五个版本化Skill：异常影响研判、经验检索与替代核验、应急供货调查、恢复方案决策、执行跟踪与重规划。Skill是可复用任务契约（输入、步骤、工具、输出、权限），不是五个Agent。
MCP通过本机子进程stdio实际交换JSON-RPC。客户端完成initialize、initialized、tools/list、tools/call；服务器白名单工具、schema验证、限定资料、超时停止。工具返回可核验内容，不接受文档中的指令提升权限。
界面按用户确认的 `finals_workbench_redesign_v2.md` 改为逐阶段工作台：任务输入、Agent研判、求证补充、恢复方案、执行反馈；Wiki、Skill目录与审计独立收纳。左侧导航不触发业务写入，所有阶段关联同一Run；没有运行的节点不显示完成。技术详情折叠。不展示私有思维链。

## 人类循环
Human-in-the-loop：缺资料或范围冲突时暂停；补充后重读/核验，未齐继续追问，无固定两轮上限；批准单独进行。
Human-on-the-loop：批准后查看测试系统执行状态；执行依赖变化立即作废旧审批，回到核对/人工确认。只有用户主动点击刷新时不声称持续自动监控。

## 验收
见JSON协议。必须同时通过离线对抗、真实在线模型完整主线、前端构建和真实实例联通验证。单元测试不是模型效果。未完成项保留pending，不用UI标签代替实际实现。
