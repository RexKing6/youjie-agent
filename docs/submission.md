# GOAI 无界应用初赛提交文案

## 作品名称

有界｜制造供应链异常研判与恢复计划智能体

## 一句话介绍

面向制造计划员，基于公开汽车供应链原始行，把邮件/群聊/随机事故转成可追溯影响，使用 LangGraph 编排受限工具、CP-SAT 和独立验证器生成恢复方案，并在人工批准前真实暂停。

## 作品简介

制造异常往往先出现在供应商邮件或业务群聊，影响核算、排产和审批分散在不同工具。有界将其串成安全闭环：语言模型把不可信文本转成带原文证据的候选事件；LangGraph 规划并调用快照、知识检索、影响分析和求解工具；OR-Tools CP-SAT 联合考虑 BOM、库存、供应提前期、有限产能、订单交期与恢复预算；独立验证器从输出 JSON 重查硬约束；图在人工审批处使用 checkpoint + interrupt 暂停，恢复后重新求解并核对场景/计划双 hash，最后只生成不可直接执行的草稿工单。

主演示实际使用 Mendeley CC BY 4.0 汽车供应链 `.xlsb` 原始行。系统校验文件 SHA-256，从第 61 期选取三个重复 BOM 配置，共 217 条逐车需求，聚合后数量仍为 217；每条需求、BOM、库存和容量行均可追溯。客户名称、事故邮件、应急供应商、报价、预算和审批为明确标注的模拟覆盖层。

模拟 Q2J 座椅供应延迟 48 小时后，三种 solver-verified 方案分别按时交付 91/45/0 台，使用应急件 91/45/0，恢复成本 ¥728/¥360/¥0。另有有边界的随机事故 Agent，可按 seed 生成供应延期、供应中断、库存损失、产线停机和需求激增，再走同一验证与人审链路。

## Agent 能力与闭环

1. 任务输入：供应商邮件、群聊、MES 式告警或随机演练事件。
2. 意图理解：结构化 IncidentDraft、实体白名单、原文 span、缺失/冲突检查。
3. 任务规划：LangGraph 按事故类型选择 allowlisted 查询、检索、影响和求解动作。
4. 能力调用：本地知识库、Pydantic、BOM 影响引擎、OR-Tools CP-SAT、独立 verifier。
5. 结果交付：三张结构化方案卡、排程、成本、受影响订单和证据 hash。
6. 验证反馈：32 个测试、机器可读运行 artifacts、真实 interrupt、批准/驳回分支。
7. 安全边界：人工审批、双 hash、draft-only、不连接 ERP/MES、不控制设备。

## 技术与创新

- 公开数据逐行 lineage，而不是只说“参考公开数据”。
- LangGraph 真实 checkpoint/interrupt，而不是页面变量冒充人审。
- solver 之后再用独立代码重放硬约束。
- 批准恢复后重新求解并校验双 hash，防止旧批准和候选篡改。
- 随机事故 Agent 只从合法实体和范围采样，可复现且没有执行权限。
- replay/live 模式明确分开；30/30 replay 合同只作为回归，不声称 live 准确率。

## 数据和许可

- Mendeley 数据：DOI `10.17632/pr3sdy5vp3.1`，CC BY 4.0，行业背景随机化数据。
- 代码和模拟覆盖层：Apache-2.0。
- 不含阿里云内部代码、数据、客户信息或业务规则。
- `lineage.json` 记录原工作表行号、必要转换和模拟字段。

## 适用边界

作品是隔离的决策辅助 PoC。公开数据不是企业原始流水；随机事故不代表真实风险分布；结果不能证明生产收益。系统不连接真实 ERP/MES、不发送采购、不控制设备、不替代现场人员决定。
